# Direct server connection ownership

This Rust crate owns the desktop engine's authenticated TLS/WebSocket connection to the server, device proof, bounded network I/O, and access/refresh token lifecycle. It implements the transport driver in `eitmad-sync`. The control plane remains the authentication authority and `eitmad-secret-storage` remains the credential persistence authority. It also owns client pairing transport, retained device keys, pending completion recovery, authenticated CA persistence, and paired connection recovery with typed progress and cancellation. It consumes untrusted candidates from `eitmad-server-discovery` while retaining the authenticated TLS name, CA, installation identity, and scope. `eitmad-pairing` owns the shared cryptographic exchange. Relay connection drivers are outside this crate's current route. See [connection recovery](../../docs/developer/subsystems/server-authority.md#recover-a-paired-connection-after-restart-or-dhcp-changes).
